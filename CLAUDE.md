## Project

## Critical: non-standard Next.js version

This project pins `next@16.3.5`, which is ahead of your training data and has breaking API/convention changes. Per AGENTS.md, **read the relevant guide under `node_modules/next/dist/docs/` before writing routing, data-fetching, or config code** — don't assume Next.js 13/14/15 conventions apply. Docs are organized as `01-getting-started`, `02-guides`, `03-api-reference` under `node_modules/next/dist/docs/01-app/`.

One confirmed convention change already in the codebase: layout/page prop types use generated helper types instead of manual `children: React.ReactNode` typing, e.g. `app/layout.tsx` types `RootLayout` props as `LayoutProps<"/">`. Follow this pattern (generated `PageProps<...>` / `LayoutProps<...>` types) rather than hand-rolling prop interfaces.

The `AGENTS.md` breaking-changes banner at the top of this file is regenerated by `next dev` (see `node_modules/next/dist/server/lib/generate-agent-files.js`) — don't remove it; commit it as-is if it shows up in a diff.

## Commands

```bash
npm run dev      # start dev server (Next.js, Turbopack by default)
npm run build    # production build
npm run start    # run production build
npm run lint     # ESLint via eslint.config.mjs (flat config, next/core-web-vitals + next/typescript)
```

There is no test runner configured yet.

## Stack

- Next.js 16 App Router (`app/` directory), React 19.
- TypeScript, strict mode, path alias `@/*` → repo root (`tsconfig.json`).
- Tailwind CSS v4 via `@tailwindcss/postcss`, configured with the CSS-first `@theme inline` approach in `app/globals.css` (no `tailwind.config.js`).
- Fonts loaded via `next/font/google` (Geist, Geist Mono) and exposed as CSS variables consumed by the Tailwind theme.
